Build a browser-playable 3D proof-of-concept game in this directory (/workspace/zoids_game). Personal non-commercial; real Zoids names are fine.

Concept: feel and general gameplay of MechWarrior 5: Mercenaries, but piloting Zoids.
Requirements:
1. 8 playable Zoids: Shield Liger, Blade Liger, Command Wolf, Gojulas, Zaber Fang, Iron Kong, Geno Saurer, Death Saurer. Build recognizable MOCK models from basic three.js shapes (no external assets; none are licensed for use): quadruped lions/wolf/tiger, bipedal dinos, gorilla etc, with distinct silhouettes/colors, animated leg/walk motion, and separate named part meshes. Each Zoid has different base stats (speed, turn, armor, weapon hardpoints, tonnage-like weight, price).
2. Hangar/loadout screen: pick Zoid; buy/equip weapons (e.g. pulse laser, beam cannon, missile pack, gatling, charged particle cannon, shock cannon), armor plating per part, speed boosters, maneuverability mods, etc. with weight/slot limits and C-bill style money.
3. NO overall HP bar. Damage is per body part (head, torso/core, left/right front legs, left/right rear legs or legs for bipeds, tail, weapon mounts, back mounts). Each part has its own armor+structure. Degradation: leg damage -> slower speed/turn; head damage -> HUD scrambles/targeting range reduced; weapon mount destroyed -> its weapons disabled; core destroyed -> Zoid destroyed; maybe boosters on back mounts. Show a per-part damage diagram on the HUD for player and for the targeted enemy (color-coded). Apply to enemy AI Zoids as well.
4. Camera toggle first-person / third-person with key (V). Mouse look, torso/aim reticle.
5. Large open maps with few obstacles (a few rocks/hills, large terrain, distance fog), at least 2-3 map/biome variants.
6. Mission loop: hangar + contract list (destroy targets, defend/escort or recon-lite, base assault) -> mission -> payout/summary -> repair costs / upgrades -> next contract. Persist money and loadout in localStorage. Enemy AI Zoids that move, aim, shoot, flank, use varied Zoids.
7. Keyboard and mouse only: WASD move, mouse aim (pointer lock), LMB/RMB/number keys for weapon groups, Shift boost, V camera, Tab target cycle, etc. Show controls in-game.
Tech: three.js via vendored local copy (download three.module.js into ./vendor via npm pack or curl, so it works offline) with an importmap, ES modules, plain static files, no build step. Must run with `python3 -m http.server 8080` in the directory and be easy to host. Organize into several JS modules.
Also: write README.txt (plain text, not markdown) with run instructions, controls, features, mock-model notes and known gaps. Add a simple test script (e.g. a Node or headless Chrome script; /usr/bin/google-chrome exists; use puppeteer-core or chrome --headless with --dump-dom/--screenshot, or a Node unit test for damage logic) to verify the game loads without console errors and that the damage/degradation logic works. Run the game headless, fix any errors, and take a screenshot of hangar and in-mission. Do the work end to end, then summarise what works and the gaps.
